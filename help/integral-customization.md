# 管理员积分商城改造说明

## 业务规则

- 新积分只能由已登录的后台管理员发放，填写正整数和操作原因，流水记录操作管理员。
- 可用积分用于兑换礼品；累计获赠积分用于排行榜。例：管理员发放 1000 分，兑换花费 300 分后，可用积分为 700，累计积分仍为 1000。
- 管理员“撤销错发积分”同时扣减可用积分和累计积分，不能超过未冻结余额或累计积分。兑换退款不增加累计积分。
- 排行榜按累计积分降序排列；同分按用户编号升序，名次连续。已停用、已注销用户不参与。仅登录用户可查看，公开字段为昵称、头像、累计积分、名次。
- 注册、签到、购物收货、线下付款、抽奖发积分已关闭；抽奖活动接口关闭。现存自动积分配置不能绕过后端限制。手机端店员改积分入口关闭，统一使用后台管理员入口。
- 开放接口不能直接覆盖积分；旧远程同步登录会直接信任外部用户编号与资产，现已关闭，使用原有微信或账号登录。

## 后台操作

1. 在后台用户列表选择用户，打开“修改积分”。
2. 选择“发放积分”，填写积分数量（1～999999999）和操作原因，提交。
3. 错发时选择“撤销错发积分”，填写数量和原因。
4. 使用原有积分商城管理功能添加积分商品、设置兑换价格和库存，在积分订单中处理发货。

前台个人中心增加“积分商城”和“积分排行榜”入口；积分商城提供“我的积分 / 积分排行榜 / 兑换记录”。“我的积分”展示可用积分、累计积分、名次及积分流水。DIY 签到组件位置改为排行榜入口。

## 数据和接口

- 新接口：`GET /api/integral/rank?page=1&limit=20`，沿用登录鉴权，单页最多 50 条。
- 返回 `list`、`count`、`my`；`my` 包含 `rank`、`total_integral`、`available_integral`。
- 沿用 `user.integral`、`user_bill` 表，不需要新增表或字段。流水类型新增 `admin_award`（发放）、`admin_revoke`（撤销），`link_id` 保存后台管理员 ID。
- 累计积分只统计上述两类有效流水。旧版 `system_add` 同时用于注册奖励等场景，不能可靠判定来源，因此不会自动纳入新排行榜；原有余额和历史流水保留。已有业务数据的部署需先确认是否需要单独迁移历史管理员奖励。
- 发放及兑换在事务中锁定用户余额；库存扣减使用库存条件更新，失败时回滚。积分兑换订单详情校验当前用户归属。
- 普通购物抵扣也重新读取并锁定当前积分余额，不再根据旧余额清零。兑换订单状态日志与订单、库存、积分在同一事务中提交。删除已完成订单不会恢复累计兑换额度。

## 运行和验证

后端沿用 CRMEB 的 PHP 7.4、MySQL、Redis 和原安装部署流程；小程序源码位于 `template/uni-app`。配置后端数据库和 Redis，安装初始化后，在小程序配置中设置自己的 AppID 和 API 域名，用 HBuilderX 编译到微信开发者工具。这里的代码改动不包含服务器部署或微信发布。

回归测试在仓库根目录执行（PHP 7.4，需要 PDO SQLite、mbstring、bcmath）：

```sh
php -d extension=pdo_sqlite -d extension=mbstring crmeb/tests/admin_points.php
```

测试使用内存数据库和项目实际 ORM、业务服务，不连接生产数据库。覆盖 65 项检查：管理员编辑入口、累计积分与排行、兑换扣减、退款排除、错发撤销、非法输入、冻结余额、停用/注销用户、自动奖励与外部写入封禁、完整下单、状态日志失败回滚、旧余额抵扣、删除订单后限额以及订单详情归属。部分下单测试表从安装 SQL 提取字段，测试遇到 PHP 警告会失败。

前端行为回归测试：

```sh
node crmeb/tests/points_frontend.cjs
```

15 项检查执行实际 Vue 页面的脚本方法，用模拟 API 验证排行榜与积分明细的分页、刷新、错误提示、重试、登录跳转；不等同于微信运行时测试。另临时还原了“开放接口覆盖积分”“删除订单绕过限额”“普通订单清零新积分”三处缺陷，确认回归测试能够失败，随后恢复修复。

已完成修改文件的 PHP 语法检查，以及 5 个 Vue 页面的模板/脚本检查、新页面 SCSS 编译和页面路由注册检查。SQLite 测试不验证 MySQL 并发锁；本机 Docker 引擎检查返回 500，未启动 MySQL 集成环境。尚未完成微信开发者工具或真机端到端联调。

部署后验收：管理员发放 1000 分 → 小程序查看积分及排名 → 兑换 300 分礼品 → 确认可用 700、累计 1000、名次不变 → 后台查看订单并发货。另用两个同时提交的兑换请求验证余额和库存不能透支，并测试非管理员无法发放积分。
